# Output Dials & Fidelity Ledger（输出四拨盘与保真账本）

**Load when:** 从已有图表重绘 / 导入 / 降级，或用户指定了输出尺寸、平台、受众、细节程度。

> **与 §1 三个拨盘的关系**：SKILL.md §1 的 COMPLEXITY / DENSITY / RESTRAINT 是**风格拨盘**，在简报阶段设定，决定图「长什么样」。本文件的四个拨盘是**交付拨盘**，决定图「交付成什么」。两套并存，不替代——先定风格，再定交付。

---

## 1. 四个交付拨盘

**必须在动手画之前设定。** 定完再画，否则尺寸和细节会反复返工。

| 拨盘 | 取值 | 默认 |
|---|---|---|
| **Format** | `svg` · `html` · `png` · `html+png` | `html`（archviz 自包含优先） |
| **Size** | `doc-inline` · `doc-wide` · `slide-16x9` · `slide-4x3` · `social-og` · `social-square` · `print-a4-landscape` · `print-letter-landscape` · `fit` | `doc-inline` |
| **Detail** | `faithful` · `balanced` · `simplified` | `balanced` |
| **Audience** | `engineer` · `mixed` · `executive` | `mixed` |

### Size 同时决定 viewBox **和字号阶梯**

这是最容易忽略的一条：**投影用的图不能沿用文档字号。**

| Size | viewBox | 节点名 | sublabel |
|---|---|---|---|
| `doc-inline` | 1200×720 | 13px | 11px |
| `doc-wide` | 1440×810 | 13px | 11px |
| `slide-16x9` | 1920×1080 | **16px** | 13px |
| `slide-4x3` | 1440×1080 | **16px** | 13px |
| `social-og` | 1200×630 | 15px | 12px |
| `social-square` | 1080×1080 | 15px | 12px |
| `print-a4-landscape` | 1587×1123 (96dpi) | 13px | 10px |
| `print-letter-landscape` | 1493×1056 | 13px | 10px |
| `fit` | 由内容算 | 13px | 11px |

**`slide-*` 字号上调的原因**：投影距离远，13px 在 3 米外读不了。这不是「大一点更好看」，是可用性要求。

**`print-*` 用 96dpi 换算**，`viewBox` 单位 = CSS px。打印时由浏览器/驱动按物理尺寸缩放。

## 2. Detail 梯度（固定降级阶梯）

| 档位 | 节点上限 | 结构 |
|---|---|---|
| `faithful` | **≤24** | 分区（zoned），允许容器嵌套 |
| `balanced` | **≤12** | 单层为主，最多 2 个容器 |
| `simplified` | **≤7** | 单层，无容器 |

### 降级顺序是固定的，不许自己发明

超出上限时，**按这个顺序**依次丢弃，直到进入上限：

```
1. 装饰      → 图标、纹理、非语义分隔线
2. 重复      → 语义相同的兄弟节点合并为一个 + 数量标注
3. 叶簇      → 同一父节点下 ≥3 个叶子 → 折叠为一个「+N 个」节点
4. 基础设施  → 网关、负载均衡、监控、日志等支撑性组件
```

**停止条件**：进入上限即停，**不要多丢**。降级的目标是「刚好放得下」，不是「尽量简洁」。

**绝不丢的**：主路径上的节点、被用户点名的组件、连接主路径与旁路的关键边。

### `faithful` 是唯一豁免 §4 soft-cap 的档位

- 默认 soft-cap 9 nodes 在 `faithful` 下放宽到 24。
- 9 以上必须**分区**（zoned，用容器框分组）。
- 24 以上**必须拆图**，不讨论。

## 3. Audience 拨盘只管**措辞**，不管数量

这是与 Detail 的关键区别——**Audience 不减少节点，它改变节点上写什么字。**

| 节点 | `engineer` | `mixed` | `executive` |
|---|---|---|---|
| 认证服务 | `Auth Service / JWT · RS256 · :8443` | `Auth Service / 令牌校验` | `登录` |
| 消息队列 | `Kafka / topic=orders.v2 / 3 partitions` | `Kafka / 订单事件` | `订单流转` |
| 缓存 | `Redis / cluster · TTL 300s · LRU` | `Redis / 会话缓存` | `会话保持` |

规则：

- **sublabel 是第一个被砍的**：`executive` 下 sublabel 基本清空，只留节点名。
- **技术标识（端口、协议、字段类型）只给 `engineer`**。
- **动词化**：`executive` 下名词短语优先（「登录」而不是「认证服务」）。
- **数量不变**：`executive` 不等于「少画几个」——那是 Detail 的职责。如果一张 12 节点的图对高管太密，正确做法是把 Detail 降到 `balanced`，而不是靠 Audience 偷偷砍节点。

## 4. 保真账本（Fidelity Ledger）

**任何降级、合并、导入重绘之后，必须报告丢掉了什么。**

理由很直接：**用户知道原图有什么，你不报他会自己发现。** 主动报是专业，被问出来是事故。

### 格式

```
Detail: balanced · 源 12 节点 → 实绘 8 节点
合并:  「令牌有效?」决策节点 → 折为 Gateway → Auth 上的边标签
折叠:  3 个监控叶子节点 → 1 个「监控 ×3」节点
丢弃:  1 个便签（「旧路径，待下线」）—— 源中未连接
完整保留: 请求主路径（Web/Mobile → Gateway → Orders → Postgres）
```

### 硬要求

1. **四类都要出现**（合并 / 折叠 / 丢弃 / 完整保留），没有就写「无」。
2. **每条都要给理由**，不能只列名字。
3. **「完整保留」必须写**——它告诉用户什么可以放心。
4. **绝不静默丢弃**。丢一个节点和丢十个节点一样要报。

### 账本必须与降级阶梯对应

账本里的每一项，都应能追溯到 §2 的四步阶梯：

| 账本行 | 对应阶梯步骤 |
|---|---|
| 合并 | 步骤 2（重复） |
| 折叠 | 步骤 3（叶簇） |
| 丢弃 | 步骤 1（装饰）/ 步骤 4（基础设施） |

如果账本里出现了阶梯覆盖不到的项目（比如「丢了一个主路径节点」），**说明降级越界了**——回去重做，或者拆图。

## 5. 与门禁的关系

| 门禁 | 关系 |
|---|---|
| **G1 Type** | Detail 上限与 G1 的 soft-cap 是同一套数字，`faithful` 是豁免档 |
| **G3 Editorial ask** | Size 拨盘的歧义处理同 G3（1 主 + 2 备 + ≤3 问） |
| **G5 Validate** | 降级后必须出账本，账本缺失 = G5 不通过 |
| **G6 Embed** | Size 决定嵌入容器宽度；`slide-*` 不要嵌进窄栏 |

**Iron rule 追加一条**：**降级过但不给保真账本的产出，不算通过 G5。**

## 6. 检查清单

动手前：

- [ ] 四个拨盘都定了？（Format / Size / Detail / Audience）
- [ ] Size 对应的 viewBox **和字号阶梯**都套上了？（投影图不能用文档字号）
- [ ] Detail 档位的节点上限清楚？
- [ ] Audience 明确是**改措辞不改数量**？

降级后：

- [ ] 降级严格按「装饰 → 重复 → 叶簇 → 基础设施」顺序？
- [ ] 进入上限就停，没有多丢？
- [ ] 主路径节点 / 用户点名组件 / 关键边都没丢？
- [ ] 账本四类齐全（合并 / 折叠 / 丢弃 / 完整保留），每条有理由？
- [ ] 账本每项都能追溯到降级阶梯的四步之一？
