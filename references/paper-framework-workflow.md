# 论文框架图模式 · 流程（S0–S5）

> 来源：`c-narcissus/paper-framework-figure-studio-pro` v3.2.15f（MIT No Attribution, Copyright 2026 OpenAI），
> 已按 archviz-diagram 的约定**重写并精简**，剥离了原包的个人化文本与 ChatGPT 网页端专属机械。
> 上游 100 个版本化 policy 已按主题收敛到本目录 7 个文件。

## 何时进入本模式

**进入**：用户要为**论文**出框架图 / 方法总览图 / 架构图 / 流程图 / 机制图，且接受「先出候选、人工筛选、人工定稿」的协作方式。

**不进入**：海报、宣传图、封面图、展板、营销视觉、把 PPT 页面塞进图的演示页 —— 那些走 `archviz-layout` 或 Editorial Mode。

**与默认模式的关系（重要）**：archviz-diagram 默认是**代码优先**（Mermaid / ASCII / 自包含 HTML）。
本模式是全技能中**唯一要求生图通道**的模式 —— 一旦进入，出图环节**禁止**用 Mermaid / SVG / Python / Plotly / Matplotlib / Graphviz / TikZ / canvas / PPT / PDF / 截图 / 本地程序化光栅代替。
退出本模式即回到代码优先默认。这与 `archviz-sketch` 的前置条件写法一致。

**没有生图通道时**：明确告知用户本模式不可用，并给出两条路 —— ① 用默认代码优先模式出**结构正确的 Mermaid/HTML 草图**（可读但非 publication-ready）；② 先做 S0/S1/S3/S4 的**纯文本阶段**（这些阶段本来就不出图），把 prompt 包攒下来，等有通道再跑 S2/S5。

## 六阶段

| 阶段 | 类型 | 做什么 | 结束条件 |
|---|---|---|---|
| **Bootstrap / plan-only** | TEXT | 只说明建议从 S0 开始、列缺失输入与环境假设、给可复制的 S0 提示词。**不读论文、不建 state、不产出任何文件** | 用户显式说「进入 S0」 |
| **S0-PAPER-FOUNDATION** | TEXT | 读论文 → 论文基础报告、**语义精度契约**、风险登记 | 给出 S1 提示词 |
| **S1-FIGURE-STRATEGY** | TEXT | 图策略 + **S2 prompt 包准备**：8 选 4 风格组合 → `C01`–`C04` | 给出 S2 提示词（纯生图） |
| **S2-SKETCH-EXPLORE** | **IMAGE** | 只按 S1 的 prompt-index 生成 4 张第一轮候选 | 4 张全部登记 |
| **S3-DIRECTION-SELECT** | TEXT | 审 S2 候选（issue ledger）→ 汇总 → 选方向 | 给出 S4 提示词 |
| **S4-CANDIDATE-BRIEF** | TEXT | 正式候选矩阵 + **S5 prompt 包准备** → `F01`–`F02` | 给出 S5 提示词（纯生图） |
| **S5-CANDIDATE-IMAGE** | **IMAGE · 终态** | 只按 S4 的 prompt-index 生成 2 张正式候选 | **助手流程结束** |

**候选数契约（硬）**：S1/S2 只用 `C01`–`C04`；S4/S5 只用 `F01`–`F02`。不补候选、不跳号、不改名。

---

## 硬人机等待屏障（本模式的第一原则）

**每轮只执行一个被显式请求的公开步骤，做完即停。**

- 上一阶段完成、门禁通过、checkpoint 写好、提示词已给出 —— **都不构成**进入下一步的授权。下一步必须等用户新的显式消息。
- **绝不把相邻阶段合并进一次回复**：S0 不得自动跑 S1；S1 不得自动生 S2 图；S2 不得自动跑 S3；S3 不得自动跑 S4；S4 不得自动生 S5 图；S5 不得自动做任何事。
- 给出的可复制提示词是**惰性文本**，不得在同一轮回复里自己消费执行它。
- 每个文本阶段结束时，明确写出「本阶段已结束、下一步尚未执行」，并只给下一步提示词。

**为什么这条是硬规则**：这个流程的产物是图，一旦一口气跑完，中间任何一处语义错误都会放大到终图，且用户没有插入修正的机会。上游把它列为 controller 级最高优先级规则，沿用。

---

## 文本阶段 / 图像阶段的职责隔离

**文本阶段（S0/S1/S3/S4）**：只写文字、状态、清单、契约、prompt 包。**不生成任何图片。**

**图像阶段（S2/S5）**：只读 prompt-index 逐行生图 + 登记。**不写审计、排名、解释、修复建议、聚合、caption、下一步文本。**

**S2/S5 逐行原子性**：生图队列的每个单元 = 一个 `candidate_id` + 一个 `prompt_path` + 一个 `target_image_path`。
- 一次生图调用**不得**满足多于一个队列单元（哪怕运行时支持一次出多图）。
- 未镜像到该行 `target_image_path` 的图 = 孤儿，不算有效候选。
- 只要还有未完成的行，就不得宣布该阶段完成。

**S2/S5 无候选级返工**：不提供「审完再重跑某张候选」。不合意的合法出路只有三条 —— ① 用户带着已知问题选一张；② 把问题转成后续阶段的 prompt 负约束；③ 用户显式要求重跑上游阶段。S5 之后没有助手侧返工路径。

## 可复制提示词骨架

各阶段的提示词应包含：**阶段 ID + 只执行该阶段 + 本轮纯文字/纯生图声明 + 该阶段的内置职责**。

```text
请使用 archviz-diagram 的论文框架图模式，根据当前状态进入并只执行 S0-PAPER-FOUNDATION。
本轮纯文字：只执行文字、清单、契约与审计写入；不要生成任何图片。
```

```text
请进入并只执行 S1-FIGURE-STRATEGY。
本轮纯文字：不要生成任何图片。
S1 必须内置完成 S2 准备：先规划 8 个互补且内部不矛盾的风格组合，评分后取最高的 4 个，
说明每个入选组合为何互补，然后只为 C01-C04 生成 prompt 包与 prompt-index。
```

```text
请进入并只执行 S2-SKETCH-EXPLORE 的生图。
只生成 4 张，不补候选、不跳号、不改名。只生成图像，不写审计、排名、解释或下一步文本。
```

```text
请进入并只执行 S3-DIRECTION-SELECT。
本轮纯文字。S3 必须先完成对 S2 候选的 issue-ledger 审阅与汇总，再选方向。
```

```text
请进入并只执行 S4-CANDIDATE-BRIEF。
本轮纯文字。S4 必须内置完成 S5 准备：正式候选矩阵、S2 问题转负约束、
元素/路由/端口合同、可见文字白名单、边承载变量登记、内部机制计划，只为 F01-F02 生成 prompt 包。
```

```text
请进入并只执行 S5-CANDIDATE-IMAGE 的生图。
只生成 2 张，不补候选、不跳号、不改名。只生成图像，不写审计、排名、caption 或下一步文本。
```

**中断续跑**（用户说「刚才断了」时）：

```text
刚才中断了。请按论文框架图模式的要求，根据当前状态和已登记产物继续执行下一步；不要重跑已完成的步骤。
```

---

## 终态边界

S5 之后**没有**助手流程。不得创建、暗示或执行任何后续阶段 —— 包括选图、审计、修订、caption 包、SVG/PPT 交付、自动偏好交接。

用户若问「接下来还剩什么」，只回：

```text
我的任务已经完成，剩下由人类来决策。
```
