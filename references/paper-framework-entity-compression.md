# 论文框架图模式 · 重复实体族压缩

> 这是本模式**最容易画错**的一类：论文里出现多个角色 / 多个数据集 / 多个条件 / 多个阶段，
> 图就顺势变成「每个角色各一条完整流程」。结果是画面爆炸、主次不分，而且**审稿人读不出你的贡献**。

## 默认规则

> **重复实体族默认不得变成重复的完整流程泳道。**

若重复的角色 / 参与者 / 条件**共享同一条规范流程**，必须改用：

| 替代画法 | 适用 |
|---|---|
| 紧凑标记 / chips | 差异只是属性不同 |
| 只在有差异处分支 | 大部分流程相同 |
| 拓扑 / 上下文 inset | 差异在环境而非流程 |
| 对照泳道 | 要对比而非并列 |
| 仅 caption 表达 | 差异不适合上图 |
| 真并行泳道 | **仅当**确有独立流程**且**有源证据支持 |

**默认是一个规范流程**（one canonical process by default），除非源证据要求不同的分支。

## S1/S4 必做的四步

1. **分类重复实体族**（`entity_variant_classification`）—— 哪些是同一族的变体，哪些是真的不同实体。
2. **声明流程实例预算**（`process_instance_budget`）—— 这张图最多画几条完整流程。
3. **正多重性锁**（`multiplicity_positive_lock`）—— 明确「多重性体现在哪里」（标记 / 计数 / 标签），而不是靠复制流程体现。
4. **变体→泳道 风险审计**（`variant_to_lane_risk_audit`）—— 检查是否又滑回「一个变体一条泳道」。

再加一道 **对抗性生成风险审计**（`adversarial_generation_risk_audit`）—— 生图模型天然倾向于「对称铺满」，必须显式写负约束对抗它。

## 残余风险高时

若上述检查后残余风险仍高 → **停止在文本 checkpoint**，写残余风险账本，**不得**进入 S2/S5 生图。

## S3 审图时的对应违规项

审 S2 候选时，把下列情况记进 issue ledger：

- 重复实体被画成重复全流程
- 变体被升格成泳道
- 紧凑标记被展开成完整 pipeline
- 流程实例数超出预算

## S0 阶段就要锁死

这条规则的**根**在 S0 的语义精度契约（见 `paper-framework-source-fidelity.md` §5）：
S0 必须把「保留角色差异」这类含糊指令**归一化**成具体的视觉实现方式，并**显式禁止**「每个角色各画一套完整流程」。
S1/S4 **不得**把 S0 的含糊措辞重新解读成画重复全泳道的许可。

## S4 → S5 的继承

S4 必须继续继承 S0/S1/S3 的 `role_visual_realization_contract`、`process_instance_budget`、`forbidden_misimplementation_locks`。

> **S5 的正式 prompt 不得把紧凑的角色/条件标记再扩写成「每个角色一条完整 pipeline」。**
> 若要改变表示方式，必须写明**新的源证据**和**修复记录**。

## 反模式

| 反模式 | 症状 |
|---|---|
| 角色复制 | 4 个 agent → 4 条一模一样的流水线 |
| 数据集复制 | 3 个数据集 → 3 条同构 pipeline |
| 条件升格 | 「不同设置下」被画成 N 套并列系统 |
| 对称铺满 | 生图模型自作主张补齐对称格 |
| 标记膨胀 | chips 被展开回完整盒子 |
