# Connector Geometry（连接线几何铁律）

**Load when:** 手写 SVG `<path>` 连接线，或用户报告「线断掉了」「箭头接不上」「线穿过盒子」「标签被盖住」。

**为什么单独成篇**：Mermaid 会自动布线和避让，手写 SVG 不会。手写 SVG 里最容易出问题的不是配色也不是排版，是**连接线**——它们要么断在盒子外面，要么穿过不该穿的盒子，要么两条线叠在一起分不清。这六条是硬规则，违反任何一条都是自动失败。

> **适用范围**：本文件针对**手写 SVG `<path>`**。Mermaid / draw.io / Excalidraw 由各自的渲染器负责布线，不走这六条，但**「不要复制渲染器的自动布局」这条仍然成立**（见 §7）。

---

## 1. 六条铁律

### C1 — 不同轴节点之间必须走圆角直角折线，禁止斜线

两个节点的 x 或 y **不共享**时，连接线必须是正交折线（orthogonal），每个拐角是 `r=8` 的四分之一圆弧（紧凑布局最低 `r=6`）。**斜的 `<line>` 是自动失败。**

```svg
<!-- ✅ 正交折线，拐角 r=8 -->
<path d="M 240 180 L 300 180 Q 308 180 308 188 L 308 252 Q 308 260 316 260 L 376 260"
      fill="none" stroke="#a8a29e" stroke-width="1" marker-end="url(#arrow)"/>

<!-- ❌ 斜线 —— 自动失败 -->
<line x1="240" y1="180" x2="376" y2="260" stroke="#a8a29e" marker-end="url(#arrow)"/>
```

**唯一的例外**：两端 x 或 y **相同**时，可以用普通直线 `<line>`。

```svg
<!-- ✅ 同 y，直线可以 -->
<line x1="240" y1="180" x2="376" y2="180" stroke="#a8a29e" marker-end="url(#arrow)"/>
```

**肘形路径公式**（从盒子 A 的右边缘到盒子 B 的左边缘，水平优先）：

```python
def elbow_h(start, end, r=8):
    """start/end = (x, y)。水平优先的正交折线，拐角半径 r。"""
    x1, y1 = start
    x2, y2 = end
    mid_x = (x1 + x2) / 2
    if abs(y2 - y1) < 0.5:                      # 同 y → 直线
        return f"M {x1} {y1} L {x2} {y2}"
    dy = 1 if y2 > y1 else -1
    return (
        f"M {x1} {y1} "
        f"L {mid_x - r} {y1} "                   # 水平段
        f"Q {mid_x} {y1} {mid_x} {y1 + dy * r} " # 拐角 1
        f"L {mid_x} {y2 - dy * r} "              # 垂直段
        f"Q {mid_x} {y2} {mid_x + r} {y2} "      # 拐角 2
        f"L {x2} {y2}"                           # 水平段
    )
```

垂直优先（`elbow_v`）把 x/y 对调即可。

### C2 — 标签与连接线之间必须有 6–10px 可见间隙

标签**绝不能压在线上**。线必须保持可见——读者要能顺着线找到连接关系。

```svg
<!-- 线在 y=180。mask 底边在 168，间隙 12px -->
<rect x="292" y="156" width="36" height="12" rx="2" fill="#f5f0eb"/>
<text x="310" y="165" text-anchor="middle" font-size="8"
      font-family="'Geist Mono', monospace" fill="#7a8399" letter-spacing="0.06em">WRITE</text>
<!-- 线本身 -->
<line x1="240" y1="180" x2="376" y2="180" stroke="#a8a29e" stroke-width="1"/>
```

规则：
- mask rect 是**不透明**的（用 surface 色，不是 `transparent`），否则线会透过来。
- mask 底边到线描边之间留 **6–10px**。挤就取 10px。
- **mask 绝不能碰到或覆盖描边**——这是硬失败。
- 垂直段上的标签放在线的**侧面**，同样留 6–10px 水平间隙，**不要用 `writing-mode: vertical`**（不可读）。

### C3 — 连接线之间禁止重叠

两条线不能共用同一段描边路径，不能平行叠在一起，不能有任何一段画在对方上面。

- 必须交叉时 → 用**跨桥（bridge / hop）**原语（§2）。
- 自然想重叠时 → 把路由错开 **≥12px**，让每条线全程可独立追踪。
- **发现自己在叠线，说明布局有问题**：两个节点太近，或者图超预算了 → 拆成概览 + 详图。

### C4 — 多条线进出同一条边时，接点必须扇形展开

两个及以上连接线进入或离开盒子的**同一条边**时，每条线要有**自己的接点**，**任意两条线不得共用盒子上同一个点**。

沿边均匀分布，相邻接点 **≥12px**（很小的盒子最低 8px）：

```
边长为 L，该边上有 N 条连接线，第 k 条（k = 1..N）的接点位置：
    offset = L * k / (N + 1)      （从该边的起始角算起）
```

- 扇出到不同侧的，各自从自己的接点正交路由——**不要在盒子附近合并描边**。
- 同向平行的两条线，**全程**保持 ≥12px 间距，不只是接点处。

**任何一条线都不许遮住另一条。** 一眼看不出两条箭头区别，布局就失败了。

### C5 — 连接线不得穿过非端点的盒子（除几何上无法绕开）

默认**绕行**。唯一合法例外：一个横贯节点（页脚服务、横向层条）物理上位于源与目标的**唯一直线路径**上。

该例外下的三个附加要求：

1. 描边改为**虚线**（`stroke-dasharray="4,3"`），表示「借道，非交互」。
2. 标签放在线的**可见端**（通常靠近源），避免落到被穿越盒子后面。
3. **箭头标记不得落在被穿越盒子的边缘**——marker 只在真正的目标处解析。

**拿不准就绕行。** 这个例外是为「绕不开」存在的，不是省布局工作的捷径。

### C6 — 标签 mask 不得与「后画的节点」重叠

C2 保证标签不压自己的线，C6 保证标签不压盒子。

节点在标签之后绘制（painting order），**落在节点内的 mask 会被节点填充盖住**，文字就变成贴在节点边框上的一截残片。

- 标签要放在**穿过空白画布**的那一段上。从盒子右边缘出发的线，mask 起点要**越过 `x + width`**。
- **mask 完整落在节点内**是合法的——那是 badge chip，不是标签。
- mask 与 zone 容器重叠也合法（zone 先画）。

## 2. 跨桥（bridge / hop）原语

两条正交线必须在一点交叉时，用跨桥表示「跨过，不相连」：

```svg
<!-- 被跨越的线正常画 -->
<path d="M 240 180 L 400 180" fill="none" stroke="#a8a29e" stroke-width="1"/>

<!-- 跨越的线：在交叉点两侧加一个半圆拱 -->
<path d="M 320 120 L 320 168 A 12 12 0 0 1 320 192 L 320 260"
      fill="none" stroke="#a8a29e" stroke-width="1" marker-end="url(#arrow)"/>
```

拱半径 `r=12`（紧凑布局最低 8），拱的两端与交叉点各留一个 `r`。

**不要用「断开一截」代替跨桥**——断口会被读成「线断了」。

## 3. 绘制顺序（painting order）

顺序错了，前面所有几何规则都白做：

```
1. 背景 rect
2. zone / 容器（先画，标签压在它们上面是允许的）
3. 所有连接线 <path> / <line>
4. 所有节点 <rect> / <circle>（盖住线的端点，视觉上「接上」）
5. 所有标签 mask + text（在最上层，保证不被盖）
6. 图例（底部横条）
```

**核心原则：线在盒子下面。** 线的端点算到盒子边缘即可，盒子后画会自然盖住溢出的那一点，接缝看起来就干净了。

```python
def attach_point(center, half_size, angle_rad):
    """从盒子中心沿 angle 方向求边缘接点。
    half_size = (hw, hh)。返回 (x, y)。"""
    import math
    hw, hh = half_size
    dx, dy = math.cos(angle_rad), math.sin(angle_rad)
    # 求射线与矩形边界的交点参数 t
    tx = hw / abs(dx) if abs(dx) > 1e-9 else float("inf")
    ty = hh / abs(dy) if abs(dy) > 1e-9 else float("inf")
    t = min(tx, ty)
    return (center[0] + dx * t, center[1] + dy * t)
```

**常见错误**：先画节点再画线 → 线的端点在盒子中心，视觉上线从盒子内部长出来；或者端点算错，线悬在盒子外面 3px。

## 4. 自动校验

```bash
# 几何冲突检测（标签压节点、线穿非端点盒子、重叠描边）
python3 scripts/self_check.py --only geometry output/diagram.html

# 全部分类
python3 scripts/self_check.py output/diagram.html
```

`self_check.py` 的 `geometry` 分类检查：

| 检查 | 判定 |
|---|---|
| 标签 mask 与**后画的**节点 rect 相交 | FAIL |
| 两条 `<path>` 的描边路径完全重合 | FAIL |
| 连接线穿过非端点节点 rect（且非虚线） | WARN |
| 斜线 `<line>` 且两端 x/y 都不相同 | FAIL |
| 同一盒子同一条边上有两条线共用接点 | WARN |
| 标签 mask 与其连接线描边重叠 | FAIL |

> ⚠️ 这些检查是**几何近似**，不是渲染级判定。它算的是元素包围盒相交，不处理 `clip-path`、`overflow: visible`、filter bleed。真正的渲染级验证需要 headless 浏览器截图对比——那超出本 skill 的范围。**几何校验能拦住 90% 的常见错误，剩下的靠肉眼。**

## 5. 与现有门禁的关系

| 门禁 | 关系 |
|---|---|
| **G5 Validate** | 连接线几何校验并入 G5 |
| **G4 Generate** | 绘制顺序（§3）在生成阶段就要遵守，不能等校验阶段补救 |
| **自愈循环** | 「箭头交叉 / 节点重叠 / 线断掉」这三项肉眼检查，现在有了可执行版本 |

**Iron rule 追加一条**：手写 SVG 的产出，**有斜线连接或标签压线，不算通过 G5**。

## 6. 检查清单

产出含手写连接线的 SVG 前：

- [ ] 所有**非共轴**节点之间都是 `r=8` 的圆角直角折线？**没有任何斜 `<line>`？**
- [ ] 共轴连接用的是直线（没有多余的拐角）？
- [ ] 每个箭头标签的 mask 底边与描边之间有 **6–10px 可见间隙**？mask 是不透明填充？
- [ ] **没有两条线共用描边路径、平行重叠、或互相遮盖？** 交叉处用了跨桥？
- [ ] 同一盒子同一条边上多条线时，**每条有独立接点且 ≥12px 间距**？
- [ ] **没有线穿过非端点盒子？** 唯一例外的情况是虚线 + 标签在可见端 + 箭头不落在被穿越盒子上？
- [ ] **没有标签 mask 压在「后画的」节点上？**（会被节点填充裁掉）
- [ ] 绘制顺序是「背景 → zone → 线 → 节点 → 标签 → 图例」？
- [ ] `python3 scripts/self_check.py --only geometry <file>` 无 FAIL？

## 7. 不要复制渲染器的自动布局

从 Mermaid / draw.io / Excalidraw **导入**时（见 `import-redraw.md`）：

**必须丢弃**：源坐标、渲染器自动间距、自动路由、源调色板、源字体、draw.io 的斜线连接、Excalidraw 的手绘几何。

**必须保留**：组件、关系、分组、方向。

理由：Mermaid 的自动布局是为「语法正确」优化的，不是为「编辑级排版」优化的。照搬它的间距和路由，等于把渲染器的取舍继承过来——这正是「看起来像 AI 生成的」的来源之一。
