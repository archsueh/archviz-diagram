# Semantic Patterns（语义模式 —— 行为优先路由）

**Load when:** 待画的内容里**行为、状态、约束、风险**本身承载了含义（不只是「有哪些组件」）。

> **与 `diagram-types-technical.md` 的关系**：那份是**类型词汇**（五类技术图各该交代什么语义）。本文件是它**上面一层**——先按「行为」选模式，再按「布局」选类型。五类词汇仍然是选完模式后交代语义的依据，两者叠加使用，不替代。

---

## 1. 为什么分两层

一个系统里，**「长什么样」和「怎么运作」是两件事**。

「有网关、有队列、有数据库」是布局。  
「队列满了会背压、背压会触发降级、降级会打穿缓存」是行为。

只按布局选类型（「有队列 → 画个方块」），画出来的是**组件清单**，不是**系统**。读者看完知道有什么，但不知道出事时会发生什么。

**顺序**：行为优先选模式 → 模式给语义原语和更紧的预算 → 类型给布局语法。没有模式匹配时，直接选类型（回到 `structural-diagram-types.md`）。

---

## 2. 路由表

| 行为触发条件 | 模式 | 最近类型 |
|---|---|---|
| 扇入、队列深度、有限容量、瓶颈 | **扇入队列 / 瓶颈** | Data flow |
| 跨阶段反复出现「问题 / 输入 / 治理 / 输出」槽位 | **阶段框架 + 语义槽位** | Process |
| 对话或松散输入变成结构化持久产物 | **非结构化输入 → 结构化产物** | Data flow |
| 两条规则轨迹要对比 通过/失败/跳过/未达 + 首次分歧点 | **成对策略轨迹** | Flowchart |
| 信任边界 + 允许/禁止的入口或部署路径 | **安全铺装路** | Architecture |
| 按「在哪强制执行」分组控制项 | **治理 / 控制目录** | Layer stack |
| 各层防御互相补偿、残余风险向上传播 | **补偿式安全层** | Layer stack |
| 需要逐块 I/O、约束、代码链接的层级分解 | **可追溯块分解** | Tree |
| 一个主体经历阶段、等待、重试、取消、终态 | **生命周期相位图** | State machine |
| 主路径之外还有异步 / 审批 / 观测旁路 | **主路径 + 旁路** | Workflow |

匹配到多个时：**取主导行为**，不叠加模式。一个模式可以加原语，但**不引入第二套布局语法**。

## 3. 九个模式（六字段详解）

### P1 — 扇入队列 / 瓶颈

| 字段 | 内容 |
|---|---|
| **触发条件** | 多个来源汇入一个有限容量的处理点；读者需要理解「堵在哪」 |
| **语义原语** | 汇入边（≥2 条指向同一处理点）· 容量标注（`cap=N`）· 队列深度（`depth=N`）· 瓶颈高亮（accent，1 个） |
| **预算** | 来源 ≤5 · 处理点 =1（多处理点就不是瓶颈图）· 深度/容量标注 ≤2 |
| **反模式** | 把队列画成一个普通方块（丢掉了「会积压」这个信息）· 多个处理点都标 accent（瓶颈只有一个） |
| **静态回退** | 队列画成**分段矩形**，已用段实心、剩余段虚线，深度写在段内 |
| **最近类型** | Data flow（`references/diagram-types-technical.md` Data Flow） |

### P2 — 阶段框架 + 语义槽位

| 字段 | 内容 |
|---|---|
| **触发条件** | 每个阶段都要回答同样几个问题（输入是什么 / 谁治理 / 产出是什么） |
| **语义原语** | 阶段列 · 槽位行（输入 / 处理 / 治理 / 产出）· 槽位空值显式标注「—」 |
| **预算** | 阶段 ≤5 · 槽位 ≤4 类 · 单元格文本 ≤8 字 |
| **反模式** | 某些阶段缺槽位却不标「—」（读者分不清「没有」和「漏画」）· 槽位名每列都不一样（失去可比性） |
| **静态回退** | 降级为**矩阵表**——这个模式在表格里表达力几乎不损失，优先考虑直接出表 |
| **最近类型** | Process |

### P3 — 非结构化输入 → 结构化产物

| 字段 | 内容 |
|---|---|
| **触发条件** | 散乱输入（对话、文档、工单）经若干步变成有 schema 的持久对象 |
| **语义原语** | 输入云（松散、多个小形状）· 转换步骤 · 产物框（严格矩形 + 字段列表）· 校验 gate |
| **预算** | 输入项 ≤6 · 步骤 ≤4 · 产物字段 ≤6 |
| **反模式** | 输入侧画成整齐等大方块（丢掉了「散乱」这个语义）· 产物侧不写字段（丢掉了「结构化」这个语义） |
| **静态回退** | 输入侧用小尺寸错位堆叠表示松散；产物侧用单一大框 + 字段行 |
| **最近类型** | Data flow |

### P4 — 成对策略轨迹

| 字段 | 内容 |
|---|---|
| **触发条件** | 同一套规则跑两个请求，结果不同，读者要找出**首次分歧点** |
| **语义原语** | 两条并行轨迹 · 每步四态（通过 / 失败 / 跳过 / 未达）· **首次分歧标记**（accent）· 汇合点 |
| **预算** | 轨迹 =2（成对是定义的一部分）· 每轨步骤 ≤6 · 分歧点 =1 |
| **反模式** | 两条轨迹步数不等长却不标「未达」· 分歧点不标记（读者要自己比对） |
| **静态回退** | 两条轨迹并排，用连接线在分歧点处加一道竖线标记 |
| **最近类型** | Flowchart |

### P5 — 安全铺装路

| 字段 | 内容 |
|---|---|
| **触发条件** | 存在信任边界；读者要区分「允许的入口」和「禁止的捷径」 |
| **语义原语** | 信任边界（虚线框，accent 描边）· 铺装路径（实线 accent）· 禁止路径（虚线 + 叉号）· 边界穿越点（gate 标记） |
| **预算** | 边界 ≤2 · 铺装路径 =1（主路径唯一）· 禁止路径 ≤3 |
| **反模式** | 禁止路径用和允许路径一样的线型（读者分不清）· 边界不标（等于没画安全） |
| **静态回退** | 允许路径实线、禁止路径虚线 + 端点叉号；边界用带标签的虚线框 |
| **最近类型** | Architecture |

### P6 — 治理 / 控制目录

| 字段 | 内容 |
|---|---|
| **触发条件** | 控制项需要按「在哪一层被强制执行」分组 |
| **语义原语** | 层（强制点）· 层内控制项 · 每项标注强制时机（事前 / 事中 / 事后） |
| **预算** | 层 ≤5 · 每层控制项 ≤5 · 强制时机 3 档 |
| **反模式** | 控制项平铺成一列（丢掉了「在哪强制」这个分组依据）· 层序颠倒（强制执行点有自然顺序：越靠下越晚） |
| **静态回退** | 分层横条，每条内横向排列控制项 chip |
| **最近类型** | Layer stack |

### P7 — 补偿式安全层

| 字段 | 内容 |
|---|---|
| **触发条件** | 多层防御，后一层补前一层的缺口；残余风险继续向上传播 |
| **语义原语** | 层（防御）· **缺口标记**（前层的缺口）· **补偿边**（后层补前层）· 残余风险出口 |
| **预算** | 层 ≤5 · 补偿边 ≤4 · 残余风险出口 =1 |
| **反模式** | 各层画成并列独立方块（丢掉了「补偿」关系，那才是重点）· 不画残余风险出口（等于宣称零风险） |
| **静态回退** | 层垂直堆叠，缺口用缺口形标记，补偿边用向上弯曲的箭头 |
| **最近类型** | Layer stack |

### P8 — 可追溯块分解

| 字段 | 内容 |
|---|---|
| **触发条件** | 层级分解中每一块都要能追溯到 I/O、约束、和代码位置 |
| **语义原语** | 块 ID · 每块 I/O · 约束 · 代码链接 · 父子关系 |
| **预算** | 块 ≤12 · 深度 ≤4 · 每块字段 ≤4 |
| **反模式** | 块没有稳定 ID（无法追溯）· 只画层级不写 I/O（退化成普通 tree） |
| **静态回退** | 树形 + 每块右侧挂一张小字段表 |
| **最近类型** | Tree |

### P9 — 生命周期相位图

| 字段 | 内容 |
|---|---|
| **触发条件** | 一个主体经过阶段、等待、重试、取消，最终到达终态 |
| **语义原语** | 状态 · 事件（触发转移）· 守卫条件 · **等待态**（可停留）· **终态**（≥1，必须标）· 取消路径 |
| **预算** | 状态 ≤9 · 转移 ≤14 · 终态 ≥1 · 取消路径 ≤1 |
| **反模式** | 无终态（读者不知道「走完」是什么样）· 等待态和普通态同形（丢掉了「会停住」）· 重试不画回边 |
| **静态回退** | 终态用双线框；等待态用虚线框；重试用回边 |
| **最近类型** | State machine（`mermaid/state-machine.mmd`） |

### P10 — 主路径 + 旁路

| 字段 | 内容 |
|---|---|
| **触发条件** | 一条主成功路径之外，还有异步 / 审批 / 观测三类旁路（archviz 的路径语义，见 §4） |
| **语义原语** | 主路径（实线 + accent）· 异步旁路（虚线）· 审批 gate（菱形 / 锁标记）· 观测旁路（浅色细线） |
| **预算** | 主路径 =1（唯一可追）· 旁路类型 ≤3 · gate ≤3 |
| **反模式** | 所有路径同一线型（读者分不出主次）· 观测路径抢主路径注意力（它不该抢）· 主路径不唯一 |
| **静态回退** | 线型 + 线宽 + 颜色三通道同时区分，灰度下仍可辨 |
| **最近类型** | Workflow（`diagram-types-technical.md` Workflow） |

## 4. 跨模式原语：路径语义

多个模式共用的**路径样式词汇**（来自 `diagram-types-technical.md`，此处作为原语统一）：

| 路径 | 线型 | 颜色 | 语义 |
|---|---|---|---|
| **主路径** | 实线 2px | accent | 正常成功流，**全图只有一条** |
| **异步路径** | 虚线 `5,4` | ink / muted | fire-and-forget / 消息队列 / 后台 |
| **审批 / 人工** | 实线 + gate 节点 | muted + gate 用 accent | 停等态，需要外部输入才继续 |
| **观测路径** | 细线 0.5px | 最浅的 muted | trace / metrics / log 旁路，**不抢注意力** |
| **禁止 / 失败** | 虚线 + 端点叉号 | 语义红 | 不允许的路径（P5） |
| **借道** | 虚线 `4,3` | muted | 穿越非端点盒子（见 `connector-geometry.md` C5） |

**三通道原则**：主路径与旁路的区分必须**同时**用线型、线宽、颜色三个通道。只靠颜色在灰度下失效（见 `accessibility-contract.md` §3）。

## 6. 反模式（模式层）

| 反模式 | 症状 | 修法 |
|---|---|---|
| **跳过模式直接选类型** | 图看起来是「组件清单」不是「系统」 | 回到 §2 路由表，问「这里的行为是什么」 |
| **叠加多个模式** | 一张图里既有队列深度又有信任边界又有生命周期 | 取主导行为；其余拆图 |
| **模式只挂名不加原语** | 声明了「扇入队列」但没画容量和深度 | 模式的**语义原语必须全部出现**，缺一个就没落地 |
| **用模式当借口超预算** | 「因为是扇入图所以可以画 12 个来源」 | 模式只**收紧**预算，不放宽 |
| **静态回退没做** | 模式依赖的视觉区分在灰度/无 JS 下失效 | 每个模式都要有 §3 的静态回退列 |

## 7. 检查清单

- [ ] 内容里的**行为**是什么？（不只是「有哪些组件」）
- [ ] 命中了 §2 路由表的哪一行？**只命中一个**吗？
- [ ] 该模式的六个字段都落实了？特别是**语义原语全部出现**？
- [ ] 预算比类型预算更紧了，没有借模式放宽？
- [ ] 路径语义用了**三通道**（线型 + 线宽 + 颜色），灰度下仍可辨？
- [ ] 该模式的**静态回退**做了？
- [ ] 声明了模式却没画原语的情况有没有？（这是最常见的假落地）
