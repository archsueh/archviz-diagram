# Grid & Spacing（4px 基网格与间距取值）

**Load when:** 手写 SVG / HTML 的节点几何、布局间距、或用户说「看起来有点歪」「对不齐」「不够整」。

> **与 `swiss-modernist-grid.md` 的分工**：那份管**页面级模块网格**（12 列 / 8px 基线 / A0 展板 / 印刷页）。本文件管**节点级几何**——单个盒子多宽多高、盒子之间隔多远、内边距多少。两者是不同层级，不冲突。

---

## 1. 为什么是 4px

不是审美洁癖，是**消除累积误差**。人眼对「差 2px」不敏感，但对「一排盒子底边参差不齐」极其敏感。4px 基网格让所有几何值都能被整除，横竖对齐在算术上成立，而不是靠手调碰运气。

**这是「看起来像人做的」和「看起来像 AI 生成的」之间最便宜的一道分界。**

---

## 2. 哪些维度必须上网格

| 类别 | 上网格？ | 说明 |
|---|---|---|
| 节点原点（x, y） | ✅ 必须 | 全部整除 4 |
| 节点宽 / 高 | ✅ 必须 | 取 §3 允许值 |
| 节点之间的间隙 | ✅ 必须 | 取 §3 允许值 |
| 盒子内边距 | ✅ 必须 | 8 / 12 / 16 |
| 圆角半径 | ✅ 必须 | 0 / 4 / 8（见 §4） |
| 描边宽度 | ❌ 不上 | 1 / 2 是描边惯例，不上网格 |
| 字号 | ❌ 不上 | 走 §5 的字号阶梯 |
| 文本基线 y | ❌ 不上 | 由字号和 `dominant-baseline` 决定 |
| 数据推导的位置 | ❌ 不上 | 图表里由数值算出的坐标是**结果**，不是设计值 |
| 箭头 marker 尺寸 | ❌ 不上 | 由描边宽度配套 |
| `.5` 偏移 | ❌ 不上 | 1px 描边落在整数坐标上会糊成 2px，加 0.5 保持锐利 |
| 透明度 | ❌ 不上 | — |

> **规则：设计决策上网格，派生值不上网格。** 你把盒子放在 x=240 是设计决策 → 上网格。柱状图第 7 根柱子的 x 由数据算出 → 不上网格，四舍五入到整数即可。

## 3. 允许取值表

| 类别 | 允许值（px） |
|---|---|
| 节点宽 | 80 · 96 · 112 · 120 · 128 · 140 · 160 · 180 · 200 · 240 · 320 |
| 节点高 | 40 · 44 · 48 · 56 · 64 · 72 · 80 · 96 · 112 · 128 |
| 节点间距 | 20 · 24 · 32 · 40 · 48 · 64 |
| 内边距 | 8 · 12 · 16 · 24 |
| 圆角 | 0 · 4 · 8 |
| 描边 | 0.5（hairline） · 1（默认） · 2（强调） |

**取不到表里的值时怎么办**：往**上**取最近的允许值，不要自定义。自定义值是网格漂移的入口。

---

## 4. 圆角策略（与现有约定一致）

SKILL.md §6 已定：**默认锐角（0），且绝不混用。**

| 场景 | 圆角 |
|---|---|
| 流程图 / 架构图节点 | **0**（锐角，默认） |
| Editorial / 卡片 | 0 或 4 |
| 状态机状态框 | 8（圆角暗示「状态」，与流程节点区分） |
| 图例 chip / badge | 2 |

**绝不混用**：同一张图里出现 0 和 8 两种节点圆角 = 语义混乱。圆角是**语义通道**（区分节点类型），不是装饰。

---

## 5. 字号阶梯（不上网格，但要有阶梯）

字号是**角色**不是尺寸。每张图最多用 4 档：

| 角色 | 字号 | 字重 |
|---|---|---|
| 图标题 | 18–20 | 500 |
| 节点名 / 主体 | 13 | 400 |
| sublabel / 技术标注 | 11 | 400 |
| 眉标 / 轴标签 / 箭头标注 | 9–10 | 500（加 `letter-spacing`） |

> 与 SKILL.md §3 的「越大越细，越小越粗」一致：大字号用轻字重，小字号用重字重，视觉重量才平衡。

**下限 9px。** 低于 9px 在投影和打印场景不可读。

---

## 6. 常见漂移症状与修法

| 症状 | 根因 | 修法 |
|---|---|---|
| 一排盒子底边参差 | 高度不在允许值里（如 46、53） | 统一到 44 或 56 |
| 盒子间距看着不均 | 间距是算出来的（均分剩余空间） | 改用固定间隙 + 让容器宽度适应 |
| 标签离盒子忽远忽近 | 文本基线手调 | 用固定内边距 + `dominant-baseline="central"` |
| 线条发虚 | 1px 描边落在整数坐标 | 加 0.5 偏移（`x + 0.5`） |
| 整体「不够整」但说不出哪不对 | 多个维度各漂 2–3px | 跑 §7 校验，逐项归位 |

## 7. 自动校验

```bash
python3 scripts/self_check.py --only grid output/diagram.html
```

`self_check.py` 的 `grid` 分类检查：

| 检查 | 判定 |
|---|---|
| 节点 `rect` 的 x / y / width / height 是否整除 4 | 不整除 → WARN（列出具体值） |
| 节点宽高是否在 §3 允许值内 | 不在 → WARN |
| 同一张图是否混用多种圆角 | 混用 → FAIL |
| 是否出现 <9px 字号 | 出现 → FAIL |
| 字号档位是否 >4 档 | 超过 → WARN |

> 网格检查默认是 **WARN** 不是 FAIL——因为**数据推导的位置本来就该离网格**。要严格模式用 `--strict-grid`，它会把「节点原点离网格」提升为 FAIL，但会跳过带 `data-derived` 标记的元素。

## 8. 检查清单

- [ ] 所有节点原点、宽高整除 4？
- [ ] 宽高取值都在 §3 表内（没有 46、53 这类自造值）？
- [ ] 节点间距取值都在表内？
- [ ] 内边距是 8 / 12 / 16 之一？
- [ ] **同一张图只用了 1 种圆角？**
- [ ] 字号档位 ≤4 档，且最小 ≥9px？
- [ ] 1px 描边带了 0.5 偏移（不发虚）？
- [ ] `python3 scripts/self_check.py --only grid <file>` 无 FAIL？
