# 论文框架图模式 · 配色（反「AI 味」）

> **目标不是某一套固定配色，而是避开可识别的「AI 图」味。**
> 这条与本技能既有的 **Max-1-accent / No-AI-purple / 对比度必算** 是同一条规则在论文场景下的强化版 —— 不冲突，是叠加。

## 必守约束

1. **克制、出版级配色**：一个主强调色 + 一个次强调色 + 安静的中性色。除非论文语义确实需要更多类别，否则不加。
2. **偏柔化的科研色调**：muted 蓝 / 青 / 绿 / 石板灰、石墨中性、有限暖色点缀 —— 优于霓虹渐变、彩虹式分类着色、光泽紫蓝辉光、过饱和赛博色板。
3. **大面积背景保持白 / 近白 / 极浅中性**，除非用户明确要求深色图且可读性仍符合出版要求。
4. **颜色必须冗余编码**：与形状、线型、分组、标签或图标**同时**使用。**绝不**只靠颜色承载含义（色盲 + 灰阶印刷）。
5. **明确避免**：渐变光斑、bokeh/光球装饰、玻璃拟态、光泽海报打光、图库插画的戏剧感、通用 AI 蓝紫渐变、过量的高饱和色阶。
6. **颜色用来区分源证据支持的空间/路径/角色**，不用来发明新的语义类别。
7. **线稿或手稿场景必查灰阶可读性**。

## 每条候选必须记录

| 字段 | 内容 |
|---|---|
| `palette_strategy` | 配色总体策略 |
| `palette_semantic_mapping` | 颜色 → 语义的映射（不得发明类别） |
| `palette_anti_ai_artifact_rules` | 本候选明确规避的 AI 味元素 |
| `human_aesthetic_rationale` | 为什么这套配色像人设计的 |
| `color_accessibility_note` | 对比度与色盲安全说明 |

S1 的**每个入选组合**与 S4 的**每个正式候选**都要带这五项。S5 prompt 包同样必须带。

## 与本技能既有规则的对接

| 既有规则 | 落点 |
|---|---|
| Max 1 accent | 本文件约束 1（论文场景放宽到 1 主 + 1 次，需记录理由） |
| No AI-purple | 本文件约束 5（扩展为完整的「AI 味」清单） |
| 对比度必算 | 走既有的 `references/accessibility-contract.md`，本文件只补「灰阶可读」这一条 |
| 语义色（组件类型固定色） | 走既有的 `references/semantic-component-colors.md` —— 论文图若要表达「这是什么组件」仍适用 |

## 反模式

| 反模式 | 症状 |
|---|---|
| 紫蓝渐变背景 | 一眼 AI |
| 彩虹分类 | 类别数 ≠ 语义数，颜色在发明概念 |
| 光泽玻璃球 | 装饰压过信息 |
| 纯色区分 | 打印成黑白即失效 |
| 高饱和赛博板 | 与 manuscript 语境不符 |
| 深色底 + 荧光 | 除非用户明确要求且可读性过关 |
